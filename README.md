# كاشر (Casher) — نقاط بيع ومخزون محلي

تطبيق عربي لنقاط البيع وإدارة المخزون. يعمل التطبيق في المتصفح ويخزن بيانات المخزون محلياً على الجهاز.

---

## 🛠️ البنية التقنية (Tech Stack)

- **Frontend**: React 19 + TypeScript + Vite + Tailwind CSS v3 + shadcn/ui + Lucide Icons
- **Database**: PGlite داخل المتصفح، مخزنة في IndexedDB على الجهاز الحالي
- **State Management**: TanStack Query v5 + React Hook Form + Zod
- **Typography & RTL**: Modern Standard Arabic, RTL-first layout (`dir="rtl"`), خط IBM Plex Arabic، دعم الأرقام العربية الشرقية (٠-٩) للعرض والأرقام اللاتينية للمدخلات والباركود.
- **Default Currency**: شيكل إسرائيلي جديد (ILS - ₪).

> **حدود التخزين:** بيانات المنتجات والمبيعات والمخزون محفوظة في IndexedDB ضمن المتصفح. لا تتم مشاركتها أو مزامنتها بين المستخدمين أو الأجهزة، ولا يحول نشر الواجهة إلى Vercel هذا التطبيق إلى نظام ERP سحابي متعدد المستخدمين. احرص على عدم مسح بيانات الموقع من المتصفح إذا كنت تريد الاحتفاظ بالبيانات المحلية.

---

## 🚀 التشغيل المحلي (Local Development)

المشروع يعمل بالكامل دون الحاجة إلى Docker.

### 1. تثبيت الحزم:
```bash
npm install
```

### 2. تشغيل خادم التطوير:
```bash
npm run dev
```

### 3. بناء التطبيق للإنتاج:
```bash
npm run build
```

لا يلزم إعداد متغيرات بيئية أو تشغيل تهجيرات Supabase لتشغيل مخزون التطبيق الحالي. ملفات Supabase الموجودة في المشروع تخص تكاملات مستقبلية ولا تحول تخزين PGlite المحلي إلى تخزين مشترك.

## النشر على Vercel

1. ارفع المشروع إلى مستودع GitHub تملكه، ثم اختر **Add New → Project** في Vercel واستورد المستودع.
2. اترك إطار العمل **Vite** أو اختره يدوياً. استخدم `npm run build` كأمر البناء و`dist` كمجلد الإخراج.
3. لا يحتاج التطبيق في وضع التخزين المحلي الحالي إلى متغيرات بيئية أو مفاتيح Supabase للنشر.
4. انشر المشروع. إعداد `vercel.json` يعيد توجيه مسارات تطبيق SPA إلى `index.html` حتى تعمل الروابط المباشرة والتحديث على `/products` و`/movements`.

بعد النشر، ستبقى بيانات كل متصفح/جهاز منفصلة ومخزنة محلياً في IndexedDB؛ لا يوفر Vercel تخزيناً مركزياً أو نسخاً احتياطية لهذه البيانات.

## النشر على GitHub Pages

المستودع يتضمن GitHub Actions workflow يبني التطبيق إلى `dist` وينشره عند الدفع إلى `main`. استخدم **Settings → Pages → Build and deployment → Source → GitHub Actions** إذا لم يكن مصدر Pages مضبوطاً على Actions. رابط المشروع هو <https://zerooo563.github.io/casher/>.

يُبنى التطبيق لمسار المستودع `/casher/` على GitHub Pages، بينما يبقى المسار الافتراضي `/` متوافقاً مع Vercel. يعالج React Router المسارات داخل قاعدة URL الخاصة بالنشر، وينشئ الـworkflow صفحات ثابتة للمسارات الداخلية حتى تعمل عند فتحها أو تحديثها مباشرة.
