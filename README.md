# كاشر (Casher) — نقاط بيع ومخزون محلي

تطبيق عربي لنقاط البيع وإدارة المخزون. يعمل التطبيق في المتصفح ويخزن بيانات المخزون محلياً على الجهاز.

---

## 🛠️ البنية التقنية (Tech Stack)

- **Frontend**: React 19 + TypeScript + Vite + Tailwind CSS v3 + shadcn/ui + Lucide Icons
- **Database**: PGlite داخل المتصفح، مخزنة في IndexedDB على الجهاز الحالي
- **State Management**: TanStack Query v5 + React Hook Form + Zod
- **Typography & RTL**: Modern Standard Arabic, RTL-first layout (`dir="rtl"`), خط IBM Plex Arabic، دعم الأرقام العربية الشرقية (٠-٩) للعرض والأرقام اللاتينية للمدخلات والباركود.
- **Default Currency**: شيكل إسرائيلي جديد (ILS - ₪).

> 📷 **دعم قارئ الباركود وكاميرا الهاتف / الويب (Barcode & Camera Scanning):**
> النظام يدعم خيارين متكاملين لقراءة الباركود:
> 1. **أجهزة قارئ الباركود الفيزيائية (الماسحات الليزرية USB / Bluetooth):** تعمل تلقائياً مع تركيز فوري وسرعة إدخال عالية وإضافة مباشرة للسلة.
> 2. **كاميرا الهاتف أو الحاسوب (Camera Barcode Scanner):** مدعومة ومدمجة بالكامل عبر مكتبة `html5-qrcode` بنقرة واحدة على زر "مسح بالكاميرا"، مع تبديل الكاميرات الأمامية/الخلفية وإصدار تنبيه صوتي وتأكيد ليزري عند التقاط الكود.

> **حدود التخزين:** بيانات المبيعات والمخزون محفوظة محلياً في IndexedDB على هذا المتصفح والجهاز فقط. لا توجد حسابات ولا تسجيل دخول — كل جهاز مستقل تماماً. لا تتحول بيانات POS إلى سجل سحابي إلا عبر الدفع الصريح من صفحة «المزامنة السحابية» أثناء مرحلة تهيئة البيانات.

تبدأ قواعد البيانات الجديدة دون منتجات تجريبية. عند الترقية تُزال مرة واحدة المنتجات التجريبية المعروفة وحركات أرصدتها الافتتاحية فقط؛ لا تُمس المنتجات اليدوية، وتبقى سجلات المبيعات والحركات الأخرى محفوظة باسم المنتج بعد حذف ارتباطه. حذف المنتج يؤثر على قاعدة بيانات هذا المتصفح والجهاز فقط.

## 🚀 التشغيل المحلي (Local Development)

المشروع يعمل بالكامل دون الحاجة إلى Docker.

### 1. تثبيت الحزم:
```bash
npm install
```

### 2. تشغيل خادم التطوير:
```bash
npm run dev
```

### 3. بناء التطبيق للإنتاج:
```bash
npm run build
```

لا توجد حسابات ولا شاشة دخول — التطبيق يفتح مباشرة ويعمل دون إنترنت بعد أول تحميل (باستثناء المزامنة السحابية المؤقتة أدناه).

## الكتالوج السحابي المشترك (مؤقت — مرحلة تهيئة البيانات)

مساحة عمل مشتركة واحدة **بدون حسابات**: كل من يملك رابط التطبيق المنشور يستطيع الدفع والسحب. تُستخدم فقط لإدخال ~5000 منتج تعاونياً، ثم تُعطّل.

**الإعداد المطلوب مرة واحدة:** أنشئ مشروع Supabase مستضافًا، أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` إلى `.env.local`، ثم ادفع التهجيرات إلى المشروع:
```bash
npx supabase db push --db-url "postgresql://postgres:<DB_PASSWORD>@db.<PROJECT_REF>.supabase.co:5432/postgres"
```
يشمل ذلك `20261010000003_shared_product_catalog.sql` (الجدول + سياسات anon لمساحة العمل + دالتي النشر والقراءة) و`20261011000000_shared_workspace.sql` (صف مساحة العمل).

من صفحة «المزامنة السحابية» (`/sync`) يدفع كل جهاز منتجاته النشطة بدفعات 500 (upsert آمن لا يمسح عمل الأجهزة الأخرى، والمتعارض على SKU/الباركود يُتخطّى ويُبلّغ عنه)، ويسحب الجميع الكتالوج إلى أجهزتهم برصيد صفري. يشمل الدفع الاسم والباركود والوحدة والتصنيف والتكلفة وأسعار البيع والجملة والضريبة والحد الأدنى والصورة؛ **لا يشمل كمية المخزون أو المبيعات أو الأرباح أو حركات المخزون**. الصور المشتركة محفوظة في bucket عام لصور المنتجات فقط. لا تضع `SUPABASE_SERVICE_ROLE_KEY` أو كلمة مرور القاعدة في ملفات الواجهة أو في أي متغير `VITE_`. قاعدة IndexedDB ليست مشفرة، ويمكن لمستخدم خبير على الجهاز نفسه فحص ملفات المتصفح.

## النشر على Vercel

1. ارفع المشروع إلى مستودع GitHub تملكه، ثم اختر **Add New → Project** في Vercel واستورد المستودع.
2. اترك إطار العمل **Vite** أو اختره يدوياً. استخدم `npm run build` كأمر البناء و`dist` كمجلد الإخراج.
3. أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` إلى متغيرات البيئة في Vercel لتفعيل المزامنة السحابية؛ من دونهما يعمل التطبيق محلياً فقط.
4. انشر المشروع. إعداد `vercel.json` يعيد توجيه مسارات تطبيق SPA إلى `index.html` حتى تعمل الروابط المباشرة والتحديث على `/products` و`/movements` و`/sync`.

بعد النشر، ستبقى بيانات كل متصفح/جهاز منفصلة ومخزنة محلياً في IndexedDB؛ لا يوفر Vercel تخزيناً مركزياً أو نسخاً احتياطية لهذه البيانات.

## النشر على GitHub Pages

المستودع يتضمن GitHub Actions workflow يبني التطبيق إلى `dist` وينشره عند الدفع إلى `main`. أضف `VITE_SUPABASE_URL` كـActions Variable و`VITE_SUPABASE_PUBLISHABLE_KEY` كـActions Secret في إعدادات المستودع لتفعيل المزامنة السحابية في الموقع المنشور؛ من دونهما يعمل التطبيق محلياً فقط. استخدم **Settings → Pages → Build and deployment → Source → GitHub Actions** إذا لم يكن مصدر Pages مضبوطاً على Actions. رابط المشروع هو <https://zerooo563.github.io/casher/>.

يُبنى التطبيق لمسار المستودع `/casher/` على GitHub Pages، بينما يبقى المسار الافتراضي `/` متوافقاً مع Vercel. يعالج React Router المسارات داخل قاعدة URL الخاصة بالنشر، وينشئ الـworkflow صفحات ثابتة للمسارات الداخلية حتى تعمل عند فتحها أو تحديثها مباشرة.
